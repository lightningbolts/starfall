## 0. Time model (OpenFront-style)

Starfall uses the same clock shape as OpenFrontIO:

| Concept | Value |
|---|---|
| Tick | **100ms** — atomic game time; all sim mutation happens here |
| Turn | **100ms** — server batches player **intents** into a `Turn` and advances one tick |
| 1 second | **10 ticks** — write durations as `seconds * 10` |
| 20 min round | **12_000 ticks** |

**Intent → Execution:** clients send immutable intents anytime; each turn converts them into stateful executions that may run for one tick or many (moves, builds). Players can replace/cancel orders on the next turn (~100ms), so actions feel continuous even though the sim is discrete.

Normative loop: [adr/001-tick-engine.md](../adr/001-tick-engine.md).

Combat stays **instant on contact** (Lanchester); multi-tick work is for movement and production, not prolonged battles.

## 1. Galaxy structure

Systems are **nodes**; space lanes are **edges**. There is no free-form or continuous map. Expansion and attacks are only possible between adjacent nodes. Lane control and chokepoints matter because connectivity is uneven.

### Target scale

| Parameter | Target |
|---|---|
| Players | 50–100 FFA |
| Round length | 15–30 minutes |
| Nodes | ~150–300 for ~100 players |
| Connectivity | Uneven: 2-lane dead ends vs 5-lane hubs |

Position (hub vs periphery), not only node count, determines strategic strength.

### Node roles

| Role | Base output | Purpose |
|---|---|---|
| Homeworld | Defense bonus | Player start node; stronger garrison bonus |
| Core world | Population | Grows population per tick |
| Resource node | Credits (via cargo) | Stockpiles cargo; auto cargo ships run to homeworld |
| Shipyard | Ship production | Builds fleets; levels speed production only |
| Relay | None (positional) | No economy; vision. Held for position |
| Relic | High credits (via cargo) | Sparse wildcard; cargo ships like resources |

Exact rates live in [balance.md](./balance.md). Cargo rules: [rulings.md](./rulings.md) §6b.

### Lanes

**No capacity limits.** Any number of fleets and cargo ships may share a lane; render them all. Hostile contact still triggers combat. Details: [rulings.md](./rulings.md) §6.

### Vision

Base vision: **1 hop** from every owned node (nodes + fleets + fleets in transit on touching lanes). Survey drones and relay upgrades extend this — [rulings.md](./rulings.md) §2.

### Galaxy generation constraints (for later code)

Normative acceptance tests: [rulings.md](./rulings.md) §9. Summary:

- Graph is undirected and connected.
- Degree distribution is skewed (many degree-2 leaves, few high-degree hubs).
- Homeworlds pairwise ≥3 hops apart; not adjacent.
- Each homeworld ≤2 hops from ≥1 shipyard.
- Role mix roughly balanced; relics not adjacent to homeworlds.

## 2. Currencies

Two currencies, each with exactly one job — no overlap:

| Currency | Generated by | Spent on |
|---|---|---|
| **Credits** | Resource/relic **cargo delivered** to cargo sink (+ small direct trickle from homeworld/core/shipyard; + looted enemy cargo) | Ship construction, node upgrades, and **empire tech** |
| **Population** | Core worlds (capped by node level) | Invasion force committed when attacking a node |

Credits never buy invasions. Population never builds ships or techs. Ambiguity about “what a resource is for” is a design failure.

Empire research is a third *spend sink* for credits, not a third currency — see [tech-tree.md](./tech-tree.md).

## 3. Node upgrades

Every node has an upgrade path tied to what it already produces:

- Upgrading a shipyard speeds ship production — not credits, and **does not** unlock Battleships.
- Upgrading a resource node increases credit output — not population.
- Upgrading a core world increases population growth / cap — not ship build rate.
- Relays upgrade positional effects (vision range), not economy.
- Relics upgrade their credit/score output only.

Empire-wide unlocks (e.g. Battleships) live on the **tech tree**, not on node levels.

### Cost scaling

```
cost(n) = base_cost × growth^(n − 1)
```

- `growth` = **1.22** (soft exponential — early upgrades stay cheap; high levels still climb)
- **No maximum level.** Level is an unbounded integer (1 = newly owned / unupgraded).
- Output bonuses use the same shape: `base × (1 + factor)^(level − 1)`.
- Map shows the level as a **number** on the node — [visuals.md](./visuals.md).

### Capture rule: no penalty on capture

A captured node **keeps its full upgrade level** (whatever integer it reached) and passes intact to the new owner.

Rationale: the deterrent against losing a heavily upgraded node is entirely the owner’s responsibility to defend it — not a system-imposed tax on the attacker.

### UX requirements (for later UI)

- Upgraded nodes must be highly visible on the map (clear high-value targets).
- Owners must easily see which of their nodes are valuable and undefended.
- That tension is intentional and must not be softened by hidden upgrade state.

Normative look, circles + role colors + level numbers, fog, fleets, HUD: [visuals.md](./visuals.md).

## 4. Ships and fleets

Three ship tiers. **No rock-paper-scissors type counters.** Cost is the balancing lever. Power-per-credit is roughly constant across tiers; the strategic choice is **mass vs flexibility**:

| Ship | Cost | Power | Build time | Speed | Role |
|---|---|---|---|---|---|
| Fighter | Low | Low | Fast | Fast | Cheap, divisible, fast response — garrison many chokepoints or react quickly |
| Cruiser | Medium | Medium | Medium | Medium | Balanced general-purpose |
| Battleship | High | High | Slow | Slow | Concentrated power; slow inflexible commitment; vulnerable if out of position |

Skill ceiling does **not** come from type matchups. It comes from concentration of force, timing, scouting, and lane geography (see combat).

### Upkeep

**None in v1.** Pure one-time build cost. Rounds are short enough that upkeep adds bookkeeping without enough strategic payoff.

### Shipyard builds

- **Fighters / Cruisers:** any owned shipyard (any level).
- **Battleships:** owned shipyard **and** empire tech `heavy_warships` (Heavy warship development). See [tech-tree.md](./tech-tree.md).
- **Homeworld:** Fighters only, at half shipyard speed — [rulings.md](./rulings.md) §1. No role conversion in v1.

### Fleet movement defaults

- Default move: entire fleet at slowest member speed; explicit `composition` to split.
- Same-owner fleets at a node auto-merge before combat.
- `CancelMove` in transit: snap to nearer hop endpoint (halfway rule) — [rulings.md](./rulings.md) §§7–8.

## 5. Combat resolution

### Model: Lanchester’s Square Law (instant on contact)

When two opposing fleets meet at a node or in transit:

1. Compute each side’s total power: `P = Σ(ship power)` across all ships present.
2. The side with higher power wins. On a tie, both fleets are destroyed (mutual annihilation).
3. Surviving power for the winner:

   ```
   P_winner_remaining = sqrt(P_winner² − P_loser²)
   ```

4. Convert remaining power back into surviving ships by removing losses **proportionally across ship types** (by each type’s share of pre-fight power). Round down ship counts; leftover fractional power is discarded (or carried as the smallest ship remnant if needed — prefer discard for simplicity).
5. The losing fleet is destroyed entirely.

### Why this formula

Under this model, two fleets of power 100 arriving separately against a defender of power 150 both lose. The same 200 power arriving together beats 150 and keeps `sqrt(200² − 150²) ≈ 132`. That rewards scouting, timing, and combining forces — the intended high skill ceiling.

### Timing: instant resolution (v1)

Combat resolves **instantly on contact** within the tick that fleets meet. Multi-tick *battles* (attrition over many ticks) are out of scope — unlike OpenFront tile conquest, Starfall does not drip damage across ticks.

Lane travel is a multi-tick **execution**; that travel time is the defender’s reaction window. Orders can be changed every turn (~100ms).

### Contact locations

- Two hostile fleets occupying the same node after movement resolution → combat.
- Two hostile fleets meeting on the same lane segment in the same tick → combat (survivors continue toward their destinations — v1).
- **Three or more** sides: merge same-owner, then pairwise Lanchester chain (strongest vs next) — [rulings.md](./rulings.md) §6.

Alliance members do not fight each other while the alliance is active (see diplomacy).

## 6. Annexation

Winning the fleet fight at a node does **not** automatically capture it.

Population is **embarked on a fleet** (`CommitInvasion`); the annexation check runs at the destination after movement and combat. Full logistics: [rulings.md](./rulings.md) §§3–4.

After defending fleets at the node are cleared (or the node is unowned with no hostiles):

1. Attacker’s committed **population** on a fleet at that node must exceed the node’s **garrison** (base + upgrades + tech bonuses; neutrals use L1 role garrison with no owner techs).
2. Enemy-owned nodes require ≥1 escort ship when the check runs. Unowned nodes may be claimed with a pop-only fleet.
3. If population is insufficient or escort invalid, committed pop is **consumed** (no refund); ownership unchanged.
4. On success, ownership transfers with **upgrades intact** (section 3); committed pop is consumed.

### Garrison

- Every node has a garrison value used only for annexation checks (not a free combat fleet).
- Garrison **scales with upgrade level** for owned nodes.
- Homeworlds have a higher base and/or multiplier.
- Values: [balance.md](./balance.md). Tech modifiers: [tech-tree.md](./tech-tree.md).

### Neutrals

Unowned nodes are claimable via the same annexation rule — ships alone never flip ownership ([rulings.md](./rulings.md) §4).

## 7. Diplomacy (lightweight)

| Feature | v1 |
|---|---|
| Propose / accept alliance | Yes |
| Shared vision | Yes (allied fog revealed to both) |
| Safe passage | Yes (allied fleets do not auto-combat; may share nodes) |
| Hard enforcement | **No** — betrayal is allowed; breaking alliance is immediate |

No binding treaties, no shared credit pools, no forced joint win in FFA score mode (allies still score independently unless a future mode says otherwise).

---

## 8. Win condition

| Condition | v1 |
|---|---|
| Primary | **Score at time limit** (territory / points — see balance weights) |
| Bonus | Elimination of all others (instant win if only one player remains with territory) |

Score is snapshotted every tick or at end; end-of-round ranking uses the final snapshot.

---

## 9. Explicit non-goals (v1)

- Rock-paper-scissors ship counters
- Continuous / free-form movement
- Ship upkeep
- Multi-tick ongoing battles
- Hard alliance enforcement or team-win FFA
- Capture-downgrade or scorched-earth taxes on takeover
- Complex trade markets between currencies
- Deep tech prerequisite chains or per-node research
- Tech effects that change combat power-per-credit or type matchups
